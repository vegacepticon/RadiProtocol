# Slices: Create snippet from selected text (Runner footer + command) and Insert snippet modal UX fixes (jumping, keyboard nav, name-only display)

## Slice 1: Pre-fill snippet editor from selection + standalone create-snippet command
**Scope:** Add the shared `initialTemplate?: string` option to `SnippetEditorOptions` and thread a 4th `initialTemplate: string = ''` parameter through `emptyMdTemplateDraft()` into the constructor create-mode branch, so the chip editor's textarea (`mountChipEditor` reads `draft.template` directly) mounts pre-filled with the supplied text and `handleSave()`'s `draftToSave` spread (`snippet-editor-modal.ts:536-537`) carries it into `SnippetService.save()` untouched. Then add a standalone `create-snippet` command in `main.ts` mirroring `handleInsertSnippet()` (`main.ts:96-100`): read the active `MarkdownView` via `getActiveViewOfType`, pre-fill `initialTemplate` from `editor.getSelection()` (empty when no selection or no active md view), construct `new SnippetEditorModal(app, this, { mode: 'create', initialFolder: this.settings.snippetFolderPath, initialTemplate })`, `open()`, await `modal.result`, show a `Notice` on save. Existing create-mode caller `SnippetManagerView.openCreateModal()` compiles unchanged because the new field is optional.
**Draws on:** `src/views/snippet-editor-modal.ts:30-48` (SnippetEditorOptions, no initialTemplate field), `src/views/snippet-editor-modal.ts:71-83` (emptyMdTemplateDraft factory hard-coding `template: ''`), `src/views/snippet-editor-modal.ts:129-137` (constructor create-mode branch calling the factory), `src/views/snippet-editor-modal.ts:384` (mountChipEditor call site — the create-mode chip editor mounts from `templateDraft` which carries `draft.template`), `src/views/snippet-editor-modal.ts:536-537` (md-template draftToSave spread), `src/views/snippet-editor-modal.ts:553` (create-mode safeResolve), `src/views/snippet-chip-editor.ts:125` (`templateArea.value = draft.template` — the textarea pre-fill path the whole outcome rests on), `src/views/snippet-manager-view.ts:258-267` (openCreateModal reference caller pattern), `src/main.ts:96-100` (addCommand registration block), `src/main.ts:285-297` (handleInsertSnippet body — the pattern to mirror: activeFile guard, `new InsertSnippetModal(app, this)`, `modal.open()`, `await modal.result`, then `getActiveViewOfType(MarkdownView)` + `editor` access; create-snippet replaces `editor.replaceSelection` with `editor.getSelection()` for pre-fill)
**Depends on:** none
**Out of scope:** The Runner footer icon and its text-selection detection (Slice 2); all Insert snippet modal UX fixes (Slices 3–5).

## Slice 2: Create snippet from selection in Runner footer
**Scope:** Add an always-visible create-snippet icon button to the `InlineRunnerModal` footer, recreated on every `render()` next to the close button (the footer is torn down and rebuilt each render at `inline-runner-modal.ts:426-434`, so the icon must be re-added in that block — not just in `buildContainer()`). The button is disabled (greyed) until text is selected in `contentEl`, following the icon-button pattern of the Back button at `inline-runner-modal.ts:554-596` (`createButton` + `setIcon` + `addEventListener`). Add a `mouseup`/`selectionchange` listener on `contentEl` (plain div at `inline-runner-modal.ts:325-326`) using `window.getSelection()`/`selection.toString()` to toggle the button's enabled state; follow the existing listener add/remove lifecycle (`boundKeyHandler` added in `open()`, removed in `close()`). On click, open `new SnippetEditorModal(app, this.plugin, { mode: 'create', initialFolder: this.plugin.settings.snippetFolderPath, initialTemplate: selection.toString() })`. `SnippetEditorModal` is a real Obsidian `Modal` mounting to `document.body`, so it stacks above the inline runner overlay — verify stacking in validation (precedent `c0bb3ee`).
**Draws on:** `src/views/inline-runner-modal.ts:301-344` (buildContainer DOM shell + close button), `src/views/inline-runner-modal.ts:325-326` (contentEl plain div, selection source), `src/views/inline-runner-modal.ts:426-434` (render footer teardown + close-button recreation), `src/views/inline-runner-modal.ts:554-596` (renderFooterIcons icon-button pattern), `src/views/inline-runner-modal.ts:226-227` (open() — `this.boundKeyHandler = (e) => this.handleKeydown(e); containerEl.addEventListener('keydown', this.boundKeyHandler)`; the add-listener lifecycle to mirror for the selection listener), `src/views/inline-runner-modal.ts:251-254` (close() — `containerEl.removeEventListener('keydown', this.boundKeyHandler)` + null-out; the remove-listener lifecycle to mirror), `src/views/inline-runner-modal.ts:672-695` (handleKeydown bails for INPUT/TEXTAREA — no conflict), `src/views/snippet-editor-modal.ts:30-48` (initialTemplate option added in Slice 1), `src/views/snippet-manager-view.ts:258-267` (openCreateModal await-result pattern)

## Slice 3: Insert snippet modal pinning — no jumping on keystroke
**Scope:** Stop `InsertSnippetModal` (extends Obsidian `Modal`, auto-centers vertically on content-height change) from recentering on every keystroke. Add `modalEl.addClass('rp-insert-snippet-modal')` in `onOpen()` following the `SnippetEditorModal` CSS-scoping pattern (`snippet-editor-modal.ts:151-153` casts to access protected `modalEl`). Add scoped CSS overriding Obsidian's vertical centering (pin near top: `margin-top`/`top: 0; bottom: auto`) and stabilize the body height so the `renderSearchResults()` removal+rebuild (`removeBody(host)` then bare `.rp-stp-list` recreated directly on `host`, not wrapped in `.rp-stp-body`) does not change outer dimensions. The insert host `.rp-insert-snippet-picker-host` currently gets only width CSS (`snippet-tree-picker.css:222-228`) — no height treatment — unlike `.rp-stp-modal-host .rp-stp-body { height: 360px }` (`:27`) and `.rp-stp-modal-host .rp-stp-list { min-height: 240px }` (`:249-250`) which apply only to the Snippet Manager move-to modal. The async-gap blank-jump was already fixed by `fed8242`; this slice addresses the remaining height-recentering symptom via CSS only.
**Draws on:** `src/views/insert-snippet-modal.ts:8` (InsertSnippetModal extends Modal), `src/views/insert-snippet-modal.ts:21-43` (onOpen creates .rp-insert-snippet-picker-host, mounts SnippetTreePicker file-only), `src/views/snippet-editor-modal.ts:151-153` (modalEl.addClass CSS-scoping pattern), `src/views/snippet-tree-picker.ts:316` (removeBody — keeps only `.rp-stp-search`, tears down every other child of `host`; the rebuild the height-stabilization must survive), `src/views/snippet-tree-picker.ts:416-473` (renderSearchResults — `removeBody(host)` then bare `.rp-stp-list` recreated directly on `host`, not wrapped in `.rp-stp-body`; the structure whose outer dimensions the CSS must pin), `src/styles/snippet-tree-picker.css:14-23` (.rp-stp-body min-height: 280px — drill view only), `src/styles/snippet-tree-picker.css:27` (.rp-stp-modal-host .rp-stp-body height: 360px — not applied to insert host), `src/styles/snippet-tree-picker.css:148` (.rp-stp-list max-height: 320px, no min-height in insert context), `src/styles/snippet-tree-picker.css:222-228` (.rp-insert-snippet-picker-host width-only, no height), `src/styles/snippet-tree-picker.css:249-250` (.rp-stp-modal-host .rp-stp-list min-height: 240px — not applied to insert host)
**Depends on:** none
**Out of scope:** Keyboard navigation (Slice 4) and name-only display (Slice 5); the create-from-selection flows (Slices 1–2).

## Slice 4: SnippetTreePicker keyboard navigation (ArrowUp/Down + Enter)
**Scope:** Implement keyboard navigation inside `SnippetTreePicker` itself so every consumer (Insert snippet modal + Runner snippet-pick at `render-snippet-picker.ts:90`) gets it for free. Add a `highlightedIndex`/`highlightedRowEl` field, a `keydown` listener on the search input handling `ArrowUp`/`ArrowDown` (move highlight, `row.scrollIntoView({ block: 'nearest' })`) and `Enter` (dispatch the highlighted row's `onSelect` callback, flowing through the identical load/guard/close path both consumers already wire), a `.rp-stp-row-highlighted` class, and reset the highlight on every re-render (old DOM removed via `removeBody`). Broaden `removeListenersExceptSearch()` to also preserve `entry.type === 'keydown'` on `searchInputEl`, or the new listener is silently dropped on the first search re-render. Add new i18n keys (e.g. highlight aria-label) to **both** `src/i18n/locales/en.json` and `src/i18n/locales/ru.json`. `InlineRunnerModal.handleKeydown()` bails for `INPUT`/`TEXTAREA` targets (`inline-runner-modal.ts:672-695`), so arrow keys in the picker's search box won't be consumed by the runner.
**Draws on:** `src/views/snippet-tree-picker.ts:62-72` (SnippetTreePickerOptions), `src/views/snippet-tree-picker.ts:108-138` (mount() — builds `.rp-stp-root`, the search input row, and calls `renderDrillView`; the keydown listener must be added inside this method), `src/views/snippet-tree-picker.ts:130` (`addListener(searchInput, 'input', ...)` — the existing input listener the new keydown listener sits alongside, establishing the addListener convention), `src/views/snippet-tree-picker.ts:168` (removeListenersExceptSearch keeps only search-input input — broaden to preserve 'keydown'), `src/views/snippet-tree-picker.ts:377-380` (renderFileRow path-div gate — shared cite with Slice 5 is fine), `src/runner/render/render-snippet-picker.ts:90` (Runner snippet-pick consumer, gets keyboard nav for free), `src/views/inline-runner-modal.ts:672-695` (handleKeydown bails for INPUT/TEXTAREA — no conflict), `src/i18n/locales/en.json` (snippetTreePicker namespace, add keys to both en + ru)
**Depends on:** none
**Out of scope:** Name-only display / hideSearchResultPath (Slice 5); modal pinning/geometry (Slice 3); the create-from-selection flows (Slices 1–2).

## Slice 5: SnippetTreePicker name-only display via hideSearchResultPath
**Scope:** Add a `hideSearchResultPath?: boolean` option flag to `SnippetTreePickerOptions` (default `false`); the path-div guard in `renderFileRow()` (`snippet-tree-picker.ts:377-380`) becomes `if (isSearchResult && !this.options.hideSearchResultPath)`. Pass `hideSearchResultPath: true` from `InsertSnippetModal.onOpen()` only — preserves disambiguation in Snippet Manager move-to where same-named snippets in different folders need the path. This is a display rule only, orthogonal to keyboard navigation; it touches the same `renderFileRow` path-div gate that Slice 4 cites but does not alter the highlight/keydown mechanics, so the two slices compose without coupling.
**Draws on:** `src/views/snippet-tree-picker.ts:62-72` (SnippetTreePickerOptions, no hideSearchResultPath field), `src/views/snippet-tree-picker.ts:377-380` (renderFileRow path-div gate, gated by isSearchResult), `src/views/insert-snippet-modal.ts:21-43` (onOpen mounts SnippetTreePicker file-only — add hideSearchResultPath: true here)
**Depends on:** none
**Out of scope:** Keyboard navigation (Slice 4); modal pinning/geometry (Slice 3); the create-from-selection flows (Slices 1–2).
