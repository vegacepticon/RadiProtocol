# Slices: Runner footer button removal, JSON snippet cleanup + README, text-block deprecation, default Start node, insert-snippet modal CSS

## Slice 1: Remove create-snippet-from-selection footer button
**Scope:** Remove the create-snippet-from-selection icon button from the inline-runner footer (right of the close X), plus all of its private machinery: the `createSnippetBtnEl` and `boundSelectionHandler` fields, the `mouseup` (contentEl) and `selectionchange` (document) listeners wired in `open()`, the `leftGroup` flex wrapper (no longer needed once the close button can revert to a direct footer child), the three private methods (`getSelectedContentText`, `updateCreateSnippetButtonState`, `handleCreateSnippetFromSelection`), the cleanup in `close()`, the now-dead `.rp-runner-footer-left` CSS rule, the unused `SnippetEditorModal` import, and the `protocolRunner.createSnippetFromSelection` i18n key from both locales. `SnippetEditorModal` itself and `.rp-runner-icon-btn:disabled` CSS are kept (3 other callers; shared disabled styling). No tests reference the button.
**Draws on:** `src/views/inline-runner-modal.ts:79-81` (field declarations); `src/views/inline-runner-modal.ts:12` (SnippetEditorModal import); `src/views/inline-runner-modal.ts:233-239` (listener wiring); `src/views/inline-runner-modal.ts:446-473` (footer render teardown + leftGroup + button); `src/views/inline-runner-modal.ts:739-775` (three private methods); `src/styles/inline-runner.css:341-347` (`.rp-runner-footer-left` CSS); `src/i18n/locales/en.json` + `ru.json` (`protocolRunner.createSnippetFromSelection`); `src/main.ts:110-113` and `src/views/snippet-manager-view.ts:241-262` (keep-alive callers of `SnippetEditorModal`).
**Depends on:** none
**Out of scope:** Footer zone restructuring (only the button and its wrapper are removed, not the zone layout); any change to `SnippetEditorModal` or its other callers; the runner's snippet resolution path (touched by Slice 2, not here).

## Slice 2: Remove JSON snippet code support and rewrite README
**Scope:** Rip out `JsonSnippet` from the `Snippet` kind union and every code path that routes on it, so the README can truthfully state snippets are `.md` only (plain `MdSnippet` + frontmatter `MdTemplateSnippet`). Drop the `.json` branches in `snippet-service.ts` `list()`/`load()`/`save()` (and `sanitizeJson` if it becomes unused), remove `JsonSnippet` from `snippet-model.ts` (and `renderSnippet`/`SnippetFile` alias if unused), drop the json validation gate and placeholder-fill arm in `insert-snippet-modal.ts`, drop the `.json` glyph in `snippet-tree-picker.ts` `fileGlyph()`, and drop the `.json`-first resolution + json arms in `inline-runner-modal.ts` runner snippet resolution. Then rewrite the README (en + ru, mirrored bilingual structure): remove the stale Canvas sections and the phantom "Convert Canvas protocol to .rp.json" command mention, remove the intro `.canvas` clause, correct the placeholder type list to the live `'free-text' | 'choice'` union, and document the two `.md` snippet formats. Migration story for existing `.json` snippet files in user vaults is an open design decision (silently stop loading, migration notice, or converter).
**Draws on:** `src/snippets/snippet-service.ts:124-141` (list `.json` branch); `src/snippets/snippet-service.ts:180-197` (load routing); `src/snippets/snippet-service.ts:225-237` (save kind branches + `sanitizeJson`); `src/snippets/snippet-model.ts:24-47,93` (`JsonSnippet` + union); `src/snippets/snippet-model.ts:10-13,107-126` (placeholder union + legacy validation); `src/views/insert-snippet-modal.ts:61-78` (json arm); `src/views/snippet-tree-picker.ts:40-44` (`.json` glyph); `src/views/inline-runner-modal.ts:1063-1075` (runner `.json`-first resolution); `README.md:7,13,48,58,60,63-68,72-75` (English edit inventory); `README.ru.md:7,13,48,58,60,63-68,72-75` (Russian edit inventory); `src/main.ts:39-115` (no canvas-convert command registered — confirms phantom).
**Depends on:** none
**Out of scope:** `MdTemplateSnippet` (the modern placeholder format, stays); the orphaned `canvasParser.*` i18n keys (test-only, optional cleanup); the `.json` → `.md` migration tooling (deferred to design as an open question).

## Slice 3: Deprecate text-block node (not creatable, still runnable)
**Scope:** Apply the "not creatable, still runnable" strategy to the text-block node kind. Keep `'text-block'` in `RPNodeKind`, `TextBlockNode` in `RPNode`, the parser case, the runner `case 'text-block'` arm, the `nodeLabel` case, and `NODE_KIND_DEFAULTS['text-block']` so existing `.rp.json` files still parse, render, edit, and run (including `snippetId`-bearing text-blocks). Remove `'text-block'` only from `EDITABLE_NODE_KINDS` so neither `openNodeKindPickerAtWorldPoint` nor `openNodeKindPickerAndConnectAtWorldPoint` offers it for new creation. Whether the "Start from specific node" picker (`node-picker-modal.ts`) should also stop surfacing text-blocks is an open design question (existing text-blocks remain runnable, so they may still be valid start points).
**Draws on:** `src/views/protocol-editor-view.ts:248-256` (`NODE_KIND_DEFAULTS` + `EDITABLE_NODE_KINDS`); `src/views/protocol-editor-view.ts:769-784` (`openNodeKindPickerAtWorldPoint`); `src/views/protocol-editor-view.ts:819-824` (`openNodeKindPickerAndConnectAtWorldPoint`); `src/graph/graph-model.ts:13,47-52,119` (`RPNodeKind`, `TextBlockNode`, `RPNode`); `src/protocol/protocol-document-parser.ts:27-36,210-218` (`VALID_KINDS` + text-block parse case); `src/runner/protocol-runner.ts:711-724` (`case 'text-block'` arm); `src/runner/protocol-runner.ts:736-757` (`case 'answer'` auto-advance — the absorbed auto-insert role); `src/graph/node-label.ts:23` (text-block label case); `src/views/node-picker-modal.ts:9,22-29,56-63,92-106` (start-picker text-block entries — open question).
**Depends on:** none
**Out of scope:** Removing `'text-block'` from `RPNodeKind` (deliberately avoided — would cascade across model/parser/validator/runner/color-map/picker); validator rejection of text-block-bearing protocols (softer than loop-start/loop-end precedent); the Loop→Question merge (deferred entirely).

## Slice 4: Default a Start node into newly created protocols
**Scope:** Inject a single Start node record into `createEmptyProtocolDocument()` so new protocols validate immediately (instead of failing `noStartNode`) and render a visible node on creation. Add one `ProtocolNodeRecord` at world coordinates `(0, 0)` (maps to surface center; `restoreViewportState` scrolls there by default), with the standard Start node color and `fields: {}`. The protocol layer has no existing node-ID generator (`nodeUid` is view-layer), so inline a `node-${Date.now()}-${random}` pattern or accept a `startNodeId` parameter. A single-start-node graph with no edges is valid. Update `protocol-document-store.test.ts` `create` tests to assert `nodes` length 1 and `kind: 'start'`; other test fixtures construct `ProtocolDocumentV1` directly with `nodes: []` and are unaffected.
**Draws on:** `src/protocol/protocol-document.ts:118-135` (`createEmptyProtocolDocument` — injection point); `src/protocol/protocol-document-store.ts:80-107` (`create()` calls it at `:95`); `src/main.ts:162,207-215` (`activateProtocolEditorView`/`createAndOpenProtocol` flow); `src/graph/graph-validator.ts:60-62` (`noStartNode` early return — what this fixes); `src/views/protocol-editor-view.ts:293-295` (`nodeUid` pattern to mirror); `src/__tests__/protocol-document-store.test.ts:197-218` (tests needing new assertions).
**Depends on:** none
**Out of scope:** Auto-centering/pan-to-node logic (the node is already visible at the default viewport center); seeding any edges or other node kinds; changes to `GraphValidator` (a single start node is already valid).
