# Sub-plan: Remove JSON snippet code support and rewrite README

## Synthesis Notes
- **Single input, single phase.** Only slice 2 was fanned into this cluster, so the sub-plan carries exactly one phase. No cross-slice overlaps or conflicts to reconcile within the cluster; the synthesis work is preservation + seam declaration, not merging.
- **Seam wiring (for root merge).** This cluster owns the `Snippet` union narrowing and the `SnippetService` shape. Any sibling cluster that imports `Snippet`/`JsonSnippet`/`renderSnippet`/`SnippetFile` or routes on `kind === 'json'` must be updated in lockstep — the design asserts every such callsite is inside this slice (the blast radius is self-contained: snippet-model, snippet-service, insert/inline-runner/manager/editor/fill-in views, chip editor, runner snippet picker, tree renderer, i18n, READMEs, and the five test files). The root merge should verify no other cluster's exports reference `JsonSnippet`/`renderSnippet`/`kind: 'json'`.
- **Integration with the not-found render path.** `SnippetService.load('.json')` returning `null` is wired into the existing runner not-found path (`src/runner/render/render-snippet-fill.ts:42` `renderSnippetFillNotFound`), which this cluster does not modify. The root merge should confirm no sibling cluster owns changes to that not-found path that collide with this assumption (recorded as r1).
- **i18n key removal is gated on the gate removal.** `insertSnippet.cannotBeUsed` and `inlineRunner.snippetCannotBeUsed` are referenced only by the `kind === 'json'` validation gates being removed in the same phase, so deleting them is safe within this slice. `snippetModel.legacyTypeError`/`invalidChoiceError` are retained (`validatePlaceholders` still guards `md-template`); `canvasParser.*` are left in place per slice scope.
- **README rewrite mirrors the en/ru bilingual structure** established by precedent `acd7e7c`/`8850eb5`/`d51d4fb`; version numbers are not hardcoded (per the version-drift lesson), and the phantom "Convert Canvas protocol to .rp.json" command mention is removed (its absence was confirmed at `src/main.ts:39-115`).
- **Decoupling from Slice 1.** Slice 1 removes the create-snippet-from-selection footer button and the `SnippetEditorModal` import from `inline-runner-modal.ts`. This slice does not touch those symbols. Neither slice edits the other's files (recorded as r3); root merge should still confirm the inline-runner-modal.ts edits from the two slices do not overlap line ranges — this slice edits `:1063-1075`/`:1004`/`:1094`/`:1110+` (snippet resolution + json arms), Slice 1 edits `:79-81`/`:233-239`/`:446-473`/`:739-775` (footer button).

## Risk Flags
- **r1** — Silently dropping `.json` snippet files (no notice, no converter) is the user-agreed migration policy; existing `.json` snippets in user vaults become invisible/unusable with no user-visible signal. Reviewer should confirm (a) no in-repo `.json` fixture or e2e path depends on json loading succeeding, and (b) the existing `renderSnippetFillNotFound` path is acceptable UX for a protocol referencing a now-unresolvable `.json` snippet at run time.
- **r2** — `renameSnippet` hardcoding the extension to `.md` is safe because `load()` returns `null` for non-`.md` after this slice, so no non-`.md` snippet is reachable through the manager to be renamed. A hypothetical non-`.md` snippet file would be silently renamed to `.md`. Reviewer should rule this is acceptable given the narrowed `Snippet` union (no non-`.md` kinds remain).
- **r3** — Slice 1 and this slice are asserted independent (no shared files edited, no cross-edits). Reviewer should confirm the `inline-runner-modal.ts` line ranges the two slices touch are disjoint and that neither slice's exports/imports force the other to change.

## Phase 1: Remove JSON snippet code support and rewrite README
### Changes
- `src/snippets/snippet-model.ts` — remove the `JsonSnippet` interface, the `SnippetFile` alias, and `renderSnippet` (unused once the fill-in modal switches to `renderMdTemplateSnippet`); narrow `export type Snippet = MdSnippet | MdTemplateSnippet`. Keep `SnippetPlaceholder`, `MdSnippet`, `MdTemplateSnippet`, `renderMdTemplateSnippet`, `validatePlaceholders`, `slugifyLabel` unchanged.
- `src/snippets/snippet-service.ts` — drop the `JsonSnippet` import; in `listFolder` skip `.json` entries (no `JsonSnippet` produced); in `load` return `null` for `.json` paths; in `save` keep only the `md-template` and `md` arms (drop the `json` arm); delete `sanitizeJson`; in `duplicateSnippet` drop the `kind === 'json'` arm and deep-copy placeholders for `md-template`; in `renameSnippet` fix the extension to `.md`; in `toSnippetRelativePath` narrow the strip regex to `.md`.
- `src/views/insert-snippet-modal.ts` — in `handleSelect` drop the `kind === 'json'` validation gate; in `renderSnippetForInsert` keep only the `md` and `md-template` arms.
- `src/views/snippet-tree-picker.ts` — simplify `fileGlyph()` to return `GLYPH_MD` for `.md` and the default glyph otherwise (drop the `.json`-specific branch); keep `GLYPH_FOLDER`/`GLYPH_MD` and a single default fallback glyph.
- `src/views/inline-runner-modal.ts` — in `handleSnippetFill` drop the `.json`-first resolution (load `.md` only, fall back to subdir scan for `.md`), drop both `kind === 'json'` validation gates, and remove the trailing json-with-placeholders fill arm; keep the `md` and `md-template` arms. (Do not touch the footer-button symbols Slice 1 removes — `:79-81`/`:233-239`/`:446-473`/`:739-775`.)
- `src/views/snippet-editor-modal.ts` — narrow `draftKind` to `'md' | 'md-template'`; in `cloneSnippet` remove the `kind === 'json'` arm; in `handleSave`/`computeCandidatePath` remove the json arms (extension always `.md`); in `onOpen` edit-mode type label show "Markdown" only; keep the `md-template` validation-banner gate only. No read-only/migrate path for `.json` (`load` returns null, so `.json` never reaches the editor).
- `src/views/snippet-chip-editor.ts` — narrow `EditableTemplateSnippet` to `MdTemplateSnippet`; drop the `JsonSnippet` import.
- `src/views/snippet-fill-in-modal.ts` — narrow the `snippet` field and constructor parameter to `MdTemplateSnippet`; drop the `renderSnippet` import and use `renderMdTemplateSnippet` exclusively in the submit/preview path.
- `src/views/snippet-manager/tree-renderer.ts` — narrow `TreeNodeFile.snippetKind` to `'md' | 'md-template'`; in `iconForNode` drop the `file-json` branch (always `file-text` for files).
- `src/runner/render/render-snippet-picker.ts` — remove the `kind === 'json'` validation gate before `onSnippetReady`.
- `src/i18n/locales/en.json` — remove `insertSnippet.cannotBeUsed` and `inlineRunner.snippetCannotBeUsed`. Keep `snippetModel.legacyTypeError`/`invalidChoiceError` and `canvasParser.*`.
- `src/i18n/locales/ru.json` — remove the same two keys.
- `README.md` — remove the intro `.canvas` clause and the "Existing `.canvas` protocols" section; remove the phantom "Convert Canvas protocol to .rp.json" command mention; correct the placeholder type list to "free text or choice"; rewrite the "Snippets" section to document the two `.md` formats (plain Markdown inserted verbatim; Markdown template with front-matter placeholders filled at run time); update the Setup step 3 wording from "JSON or Markdown" to "Markdown". Do not hardcode version numbers.
- `README.ru.md` — mirrored Russian rewrite of the same sections.
- `src/__tests__/snippet-model.test.ts` — remove the `renderSnippet`/`SnippetFile` describe blocks; keep `slugifyLabel` coverage.
- `src/__tests__/snippet-service.test.ts` — remove the `.json` list/load/save assertions and the `kind === 'json'`-typed fixtures; keep `.md` and `.md-template` coverage.
- `src/__tests__/snippet-service-validation.test.ts` — drop the `.json`-loaded validation cases; keep `validatePlaceholders` direct coverage for `md-template` legacy-type/invalid-choice detection.
- `src/__tests__/snippet-editor-modal.test.ts` — remove the `sampleJsonSnippet`/json-draft tests; keep `md` and `md-template` coverage.
- `src/__tests__/runner/render-snippet-picker.test.ts` — replace the `kind: 'json'` fixture with an `md-template` fixture (or remove the json-validation case now that the gate is gone).
