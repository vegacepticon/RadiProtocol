# Sub-plan (cluster-3): Insert snippet modal pinning — no jumping on keystroke

## Synthesis Notes
- **Single-slice cluster.** Only slice 3 was fanned into this cluster, so there are no intra-cluster overlaps to merge. The phase below carries the design's decisions verbatim — no redesign.
- **Cross-slice integration (from research).** Slice 3 is intentionally CSS-only + one `addClass` call and is orthogonal to the other slices in the research map:
  - Slices 1–2 (create-from-selection: Runner footer icon + command) touch `inline-runner-modal.ts`, `main.ts`, `snippet-editor-modal.ts` — **not** `insert-snippet-modal.ts:modalEl` or the insert-host height CSS. No shared file/symbol.
  - Slice 4 (keyboard nav) modifies `snippet-tree-picker.ts` JS (`removeListenersExceptSearch` keep-condition + new `keydown` listener) and adds a `.rp-stp-row-highlighted` class. Slice 3 does **not** touch `snippet-tree-picker.ts` JS and its CSS rules use the direct-child selector `> .rp-stp-list` scoped to `.rp-insert-snippet-picker-host`, so they do not collide with Slice 4's `.rp-stp-row-highlighted` rule. The two compose without coupling.
  - Slice 5 (name-only display) adds a `hideSearchResultPath` flag consumed in `renderFileRow()` and an `InsertSnippetModal`-side pass of `true`. Slice 3's `onOpen()` edit inserts the `modalEl.addClass` call as the first statement, before `contentEl.empty()` and before the `SnippetTreePicker` mount — so Slice 5's option-flag addition to the `new SnippetTreePicker({...})` call site composes cleanly. No ordering constraint beyond "Slice 3's addClass stays first in onOpen()".
- **No conflicts.** `depends_on: []` in the design, and `depends_on_clusters: []` here: this cluster can be implemented in any order relative to the others.
- **Listener-lifecycle non-intersection.** The research flags `removeListenersExceptSearch()` as a hidden coupling point for any new search-input listener (Slice 4's `keydown`). Slice 3 adds no listener and only touches CSS + `modalEl.addClass`, so it does not interact with that lifecycle.

## Risk Flags
- **r1** — The pin rule assumes Obsidian centers `.modal` via flex `align-items: center` on `.modal-container` (current behavior); `align-self: flex-start` opts out. If a future Obsidian version switches `.modal` to absolute/fixed positioning, the pin would need `top: 0; bottom: auto` instead. Reviewer: verify the pinned modal does not move vertically on any keystroke in the current Obsidian build target; if it still jumps, the pin CSS needs the absolute-positioning fallback.

## Phase 1: Pin insert-snippet modal and stabilize picker body height
### Changes
- `src/views/insert-snippet-modal.ts` — at the top of `onOpen()`, before `contentEl.empty()`, add `modalEl.addClass('rp-insert-snippet-modal')` via the protected-cast pattern used by `SnippetEditorModal` (`src/views/snippet-editor-modal.ts:151-153`):
  ```ts
  const modalEl = (this as unknown as { modalEl?: { addClass?: (cls: string) => void } }).modalEl;
  if (typeof modalEl?.addClass === 'function') {
    modalEl.addClass('rp-insert-snippet-modal');
  }
  ```
  No other JS change in this file; the existing body remains unchanged.
- `src/styles/snippet-tree-picker.css` — append immediately after the existing `.rp-insert-snippet-picker-host` width-only block (`:222-228`), extending the same host scope:
  ```css
  /* Slice 3 — Pin insert-snippet modal near the top + stabilize body height so the
     search-result rebuild (removeBody + bare .rp-stp-list on host) doesn't recenter
     the modal on every keystroke. The insert host previously had only width CSS. */
  .rp-insert-snippet-modal {
    /* Opt out of .modal-container's align-items: center; anchor to top padding. */
    align-self: flex-start;
    margin-top: 0;
  }

  .rp-insert-snippet-picker-host .rp-stp-root > .rp-stp-body {
    /* Stabilize drill view outer height (matches .rp-stp-modal-host treatment). */
    height: 360px;
  }

  .rp-insert-snippet-picker-host .rp-stp-root > .rp-stp-list {
    /* Bare search-result list recreated on host by renderSearchResults().
       Global .rp-stp-list { max-height: 320px } (line 148) still applies, so
       min==max==320px fixes the height regardless of result count. */
    min-height: 320px;
  }
  ```
  No new CSS file — `snippet-tree-picker.css` is already wired into the build via `esbuild.config.mjs` `CSS_FILES`.
