# Sub-Plan: SnippetTreePicker keyboard navigation (ArrowUp/Down + Enter)

## Synthesis Notes

- **Single-slice fan-in.** Only one design (Slice 4) was supplied for this cluster, so there are no intra-cluster overlaps to merge. The synthesis work is binding the design's decisions to the cross-slice constraints the research records, and exporting the seams the root merge will wire against Slices 1–3 and Slice 5 of the larger feature.
- **Cross-slice file overlap with Slice 5 (research-confirmed).** The research records that Slice 5 adds `hideSearchResultPath?: boolean` to `SnippetTreePickerOptions` and gates `renderFileRow()`'s path-div at `src/views/snippet-tree-picker.ts:377-380`. Slice 4 also edits `snippet-tree-picker.ts` (keydown listener in `mount()` at `:130`, broadened keep-predicate in `removeListenersExceptSearch()` at `:168`, `clearHighlight()` calls inside `renderDrillView`/`renderSearchResults`). The design's claim — "this slice adds no option flag, so the two slices compose without touching each other's contract" — holds *only if* the edit regions stay disjoint: Slice 4's changes are in `mount()` listener registration, `removeListenersExceptSearch()`, and the re-render bodies; Slice 5's are in the `SnippetTreePickerOptions` interface and the `renderFileRow` path-div gate. No overlap on a shared line. Flagged as r1 so the grade panel and validate confirm disjointness when both slices land.
- **i18n overlap with every other slice.** Both `en.json` and `ru.json` are touched by every slice in this feature (research: "i18n must be updated in BOTH en.json and ru.json simultaneously"). Slice 4 adds only `snippetTreePicker.highlightAria` under the existing `snippetTreePicker` namespace — a new key, no mutation of existing keys. Composes additively with any other slice's i18n additions as long as each merges into both locale files without dropping sibling keys. No conflict; noted for the root merge's i18n reconciliation.
- **Listener-lifecycle seam (research Lesson 5 / Integration Point).** The research explicitly calls out `removeListenersExceptSearch()` as "the hidden coupling" — a new `keydown` listener on `searchInputEl` is silently dropped on the first debounced search re-render unless the keep-predicate is broadened. Slice 4's design makes exactly this change (`:168` → `entry.el === this.searchInputEl && (entry.type === 'input' || entry.type === 'keydown')`). This is the one seam other clusters must not regress: any later slice that re-touches `removeListenersExceptSearch()` must preserve both listener types on `searchInputEl`. Exported as a seam.
- **No-conflict with Runner container keydown (research-confirmed).** `InlineRunnerModal.handleKeydown()` (`inline-runner-modal.ts:672-695`) bails for `INPUT`/`TEXTAREA` targets, so arrow/Enter keys pressed while focus is in the picker's search input never reach the Runner's Ctrl+← / Ctrl+→ / Escape handling. The two keydown layers compose without interference — no cross-slice coordination needed with the cluster that owns `InlineRunnerModal`.
- **Consumer contracts unchanged.** `SnippetTreePickerOptions`, `SnippetTreePickerResult`, and the `SnippetTreePicker` public methods keep their signatures. `render-snippet-picker.ts:90` (Runner) and `insert-snippet-modal.ts:21-43` (Insert modal) compile and mount unchanged — both inherit keyboard nav for free because navigation is internal to the picker. No integration action required by the clusters owning those consumers; the root merge only needs to confirm the no-public-surface-change invariant.

## Risk Flags
- **r1** — Slice 4 and Slice 5 both edit `src/views/snippet-tree-picker.ts` and `src/i18n/locales/{en,ru}.json`. The design asserts disjoint edit regions (Slice 4: `mount()` listener, `removeListenersExceptSearch()`, re-render bodies; Slice 5: `SnippetTreePickerOptions` interface + `renderFileRow` path-div gate at `:377-380`). Reviewer should verify the two slices' line ranges in `snippet-tree-picker.ts` do not collide and that the broadened `removeListenersExceptSearch()` keep-predicate does not regress Slice 5's path-display gate (or any other slice's listener on `searchInputEl`). Rule pass if disjoint, fail if either slice edits a line the other also touches.
- **r2** — Query-on-keypress `currentRows()` relies on every visible list row carrying `.rp-stp-folder-row` or `.rp-stp-file-row` and being a descendant of the current `.rp-stp-list`. Slice 5's name-only display change alters only the *path-div* inside `renderFileRow`, not the row's own class — so the contract should hold. But if any sibling slice restructures the search-result container (e.g. wraps results in `.rp-stp-body` per the research's "Fix shape" option B) or renames row classes, `currentRows()` could return a stale/empty set and ArrowUp/Down would silently no-op. Reviewer should confirm the row-class + `.rp-stp-list` container contract is preserved across every render path both slices touch.

## Phase 1: SnippetTreePicker keyboard navigation (ArrowUp/Down + Enter)
### Changes
- `src/views/snippet-tree-picker.ts` — add three instance fields (`highlightedIndex: number = -1`, `highlightedRowEl: HTMLElement | null = null`, `highlightStatusEl: HTMLElement | null = null`); in `mount()` create a visually-hidden `aria-live="polite"` status span inside `.rp-stp-search` and register a `keydown` listener on `searchInputEl` immediately after the existing `input` listener at `:130` (via the same `addListener` tracking convention so `unmount()`/`clearContainer()` tear it down); broaden the keep-predicate in `removeListenersExceptSearch()` at `:168` to `entry.el === this.searchInputEl && (entry.type === 'input' || entry.type === 'keydown')`; call `this.clearHighlight()` at the top of `renderDrillView()` and `renderSearchResults()` right after `this.removeBody(host)`; add private `handleSearchKeydown(e)` (ArrowDown/ArrowUp → moveHighlight, Enter → `this.highlightedRowEl?.click()`, no-op + no-throw when `highlightedIndex === -1`; ignore modifier-laden keys), `currentRows()` (`rootEl().querySelectorAll<HTMLElement>('.rp-stp-folder-row, .rp-stp-file-row')` — never cached), `moveHighlight(rows, delta)` (toggle `.rp-stp-row-highlighted` off old / on new with wrap-around modulo `rows.length`, `scrollIntoView({ block: 'nearest' })`, update aria-live status via the new i18n key), and `clearHighlight()` (reset `highlightedIndex = -1` + `highlightedRowEl = null`; old element is detached after `removeBody` so no class removal needed).
- `src/styles/snippet-tree-picker.css` — add `.rp-stp-row-highlighted` rule (background + border to mark the keyboard cursor) and a visually-hidden `.rp-stp-sr-only` helper for the aria-live status span.
- `src/i18n/locales/en.json` — add `snippetTreePicker.highlightAria` key (`"Highlighted: {name}"`) under the existing `snippetTreePicker` namespace; do not modify any existing keys.
- `src/i18n/locales/ru.json` — add `snippetTreePicker.highlightAria` key (`"Подсвечено: {name}"`) under the existing `snippetTreePicker` namespace; do not modify any existing keys.
- `src/__tests__/snippet-tree-picker.test.ts` — add Vitest suite using the `MockEl` class + `vi.fn()` host-spies pattern (per render-layer guidance), with inline `SnippetService` stubs (folders/snippets arrays) per the "construct directly, no mocking" convention; cover: ArrowDown moves `.rp-stp-row-highlighted` onto the first row then the second; ArrowUp moves back; wrap-around last→first and first→last; Enter dispatches the row's registered `click` handler (asserted via a `vi.fn()` `onSelect` spy for file rows, and via a drill-path assertion for folder rows); Enter with no highlighted row is a no-op and does not throw; after a debounced search re-render the `keydown` listener on `searchInputEl` is still active (ArrowDown moves the highlight on the freshly-rendered rows) — proves `removeListenersExceptSearch()` preserves the keydown listener; after a drill/breadcrumb navigation re-render `highlightedIndex` resets to `-1` and `highlightedRowEl` to `null`.

#### Automated Verification:
- [ ] `npm test` — new `snippet-tree-picker.test.ts` suite passes: ArrowDown/ArrowUp traversal, wrap-around, Enter dispatches the row's `click` handler (file-row `onSelect` spy + folder-row drill assertion), Enter no-op when no row highlighted, keydown listener survives a debounced search re-render, highlight resets to `-1`/`null` after a drill/search re-render.
- [ ] `npm run lint` — ESLint + Stylelint pass (including the new `.rp-stp-row-highlighted` / `.rp-stp-sr-only` CSS rules).
- [ ] `npm run build` — type-check + esbuild production bundle succeeds; `InlineRunnerModal` and `InsertSnippetModal` consumers compile unchanged (no public-surface signature change to `SnippetTreePickerOptions` or `SnippetTreePicker`).
#### Manual Verification:
- [ ] In the Insert snippet modal, typing a query then pressing ArrowDown moves the highlight onto the first row; ArrowDown again moves to the second; ArrowUp moves back; navigation wraps from last→first and first→last.
- [ ] Pressing Enter while a file row is highlighted inserts that snippet (same path as a mouse click); pressing Enter on a folder row drills in (same path as a mouse click); pressing Enter with no row highlighted is a no-op.
- [ ] After the modal re-renders on a new keystroke or a breadcrumb/drill navigation, arrow keys still work and no stale-row `.click()` fires.
- [ ] A screen reader announces the highlighted row's title on each highlight move (aria-live status span via `snippetTreePicker.highlightAria`).
- [ ] Arrow/Enter keys pressed while focus is in the picker search input do not trigger `InlineRunnerModal` Ctrl+← / Ctrl+→ / Escape handling (the runner's `handleKeydown` INPUT/TEXTAREA bail holds).
- [ ] `snippetTreePicker.highlightAria` key exists in both `src/i18n/locales/en.json` and `src/i18n/locales/ru.json`.
