# Sub-Plan: SnippetTreePicker name-only display via hideSearchResultPath

## Synthesis Notes
- **Single-slice cluster** — only slice 5 was fanned in, so there are no cross-slice overlaps to merge and no cross-cluster seams to wire. The phase below carries the design's decisions unchanged: additive optional flag (default `false`), single behavioural gate in `renderFileRow`, single opt-in site in `InsertSnippetModal`, one new test plus the existing default-`false` test kept as regression guard.
- **Composability with Slice 4 (keyboard nav) preserved** — the design explicitly notes Slice 4 and Slice 5 share the `renderFileRow` cite but operate on disjoint concerns (highlight/keydown mechanics vs. path-line visibility). Slice 5 changes only *whether* the path-div element is appended; it does not touch row identity, class list, click `onSelect`, or the re-render lifecycle that Slice 4's highlight reset relies on. No merge conflict; the two clusters integrate cleanly when the root plan composes them.
- **No `depends_on`** — slice 5's frontmatter declares `depends_on: []`, so this cluster has no ordering constraint on other clusters. It can be sequenced independently of Slice 3 (modal geometry) and Slice 4 (keyboard nav).
- **CSS untouched** — the `.rp-stp-result-path` rule at `src/styles/snippet-tree-picker.css:197` is unchanged; the flag removes the element from the DOM rather than hiding it via CSS. Slice 3 owns modal-geometry CSS; no overlap.
- **No i18n** — the flag only removes a DOM element and introduces no new user-visible copy, so no `en.json`/`ru.json` keys are required (Slice 4 owns keyboard-nav aria-label keys).

## Phase 1: Add hideSearchResultPath option and opt in from InsertSnippetModal
### Changes
- `src/views/snippet-tree-picker.ts` — Add the optional `hideSearchResultPath?: boolean` field to the `SnippetTreePickerOptions` interface (documented as default `false`, search-result-only; drill-view rows never render the path line regardless). Narrow the `renderFileRow()` path-div gate at `src/views/snippet-tree-picker.ts:381` from `if (isSearchResult)` to `if (isSearchResult && !this.options.hideSearchResultPath)`. No change to `renderFolderRow`, no change to the drill-view branch, no new fields/listeners/state, no constructor normalization (read `this.options.hideSearchResultPath` directly, matching the established `this.options.mode`/`this.options.rootPath`/`this.options.t` pattern).
- `src/views/insert-snippet-modal.ts` — In `onOpen()`, pass `hideSearchResultPath: true` alongside the existing `mode: 'file-only'` in the `SnippetTreePicker` options object constructed at `src/views/insert-snippet-modal.ts:32`. No other change to the modal.
- `src/__tests__/views/snippet-tree-picker.test.ts` — Add one test asserting that with `hideSearchResultPath: true` in file-only mode, a search-result file row renders `.rp-stp-result-name` (glyph + basename) but no `.rp-stp-result-path` element (`findFirst(container, el => el.classList.has('rp-stp-result-path'))` returns `null`). Keep the existing "result row secondary text = full relative path from rootPath" test at `src/__tests__/views/snippet-tree-picker.test.ts:647-655` unchanged as the default-`false` regression guard.
