# Sub-plan (cluster-1): Remove create-snippet-from-selection footer button

## Synthesis Notes
- **Single-slice cluster.** The fan-in provided one design (slice 1, `depends_on: []`), so there is no intra-cluster overlap to merge. The phase below carries the design's decisions verbatim; no redesign.
- **Citation fix carried through.** The design cited the close-button direct-child precedent as `inline-runner-modal.ts:170-173`; that range is actually parse logic. The real precedent is `inline-runner-modal.ts:359` inside `buildContainer()`, which already creates the close button as a direct child of `footerBtnRow` with no `leftGroup` wrapper. The sub-plan cites `:359`; the pattern claim (no new CSS needed) holds.
- **Cross-cluster seam with cluster-2 (snippet/JSON cleanup).** Research Change 2 edits `inline-runner-modal.ts:1063-1075` (runner `.json`-first snippet resolution). Those lines are disjoint from this slice's footer edits (lines 12, 78-81, 233-239, 269-275, 446-474, 738-776). Integration rule: cluster-2's edit of this same file must (a) not reintroduce the `SnippetEditorModal` import, (b) not assume `createSnippetBtnEl`/`boundSelectionHandler`/`leftGroup`/`getSelectedContentText`/`updateCreateSnippetButtonState`/`handleCreateSnippetFromSelection` exist, and (c) leave the footer rebuild written here intact. No ordering dependency between the two clusters on this file (non-overlapping line ranges); both may land in either order.
- **`SnippetEditorModal` stays.** It has three other production callers (`src/main.ts:110-113` `handleCreateSnippet`, `src/views/snippet-manager-view.ts:241-262` create/edit, `src/views/snippet-chip-editor.ts`) plus dedicated tests. Only the `inline-runner-modal.ts` import becomes unused and is dropped. Research confirms this explicitly.
- **No test edits.** Grep across `src/__tests__/` for all Phase-2 identifiers returns zero matches, so the existing inline-runner suites pass unchanged.
- **i18n sync.** The `protocolRunner.createSnippetFromSelection` key is removed from both `en.json` and `ru.json` (line 313 in each) in the same change; the only read site (`inline-runner-modal.ts:464`, the deleted button's `aria-label`) is deleted in the same slice.

## Risk Flags
- **r1** — Re-parenting the close button as a direct `footerBtnRowEl` child preserves the existing left/right split under `justify-content: space-between` across every runner state (at-node, awaiting-loop-pick, snippet-pick, content-only), with no height/zone regression. Research precedent `182cbf4` (footer layout restructure) triggered 6 follow-up fixes across runner states; this slice only *removes* a button + wrapper (no zone restructure) and mirrors the already-working `buildContainer()` shell at `:359`, so it should be low-risk — but the grade/validate panel should rule on whether manual UAT must cover all runner states, not just at-node.

## Phase 1: Remove create-snippet-from-selection footer button
### Changes
- `src/views/inline-runner-modal.ts` — Drop the `SnippetEditorModal` import (line 12). Delete the two field declarations `createSnippetBtnEl` and `boundSelectionHandler` (lines 78-81, including the `Phase 2` doc comment). Delete the selection-listener wiring block in `open()` (lines 233-239: the `Phase 2` comment, the `boundSelectionHandler` assignment, and the two `addEventListener` calls for `mouseup` on `contentEl` and `selectionchange` on `document`). Delete the selection-listener teardown block in `close()` (lines 269-275: the `boundSelectionHandler` null-guard, the two `removeEventListener` calls, and the `createSnippetBtnEl = null` line), leaving the `boundKeyHandler` teardown above and the `activeFileEventRef` cleanup below intact. Rewrite the footer rebuild in `render()` (lines 446-474) so the close button is created as a direct child of `footerBtnRowEl` (no `leftGroup` div, no create-snippet button), matching the shape already used in `buildContainer()` at `:359`: `footerBtnRowEl.empty()` → `createEl('button', { cls: 'rp-inline-runner-close-btn rp-runner-icon-btn' })` → `setIcon(closeBtn, 'x')` → `setAttribute('aria-label', t('protocolRunner.closeProtocol'))` → `addEventListener('click', () => this.close())`. `renderFooterIcons()` continues to append the Back/Redo/Skip `iconsGroup` as the second flex item. Delete the three private methods `getSelectedContentText`, `updateCreateSnippetButtonState`, `handleCreateSnippetFromSelection` (lines 738-776).
- `src/styles/inline-runner.css` — Delete the `.rp-runner-footer-left` rule and its `Phase 2` comment (lines 341-347). Keep the `.rp-runner-icon-btn:disabled` rule (lines 351-358) — it still styles the Back/Redo/Skip buttons whose `disabled` state is toggled in `renderFooterIcons`.
- `src/i18n/locales/en.json` — Remove the `"createSnippetFromSelection": "Create snippet from selection"` entry (line 313) from the `protocolRunner` object.
- `src/i18n/locales/ru.json` — Remove the `"createSnippetFromSelection": "Создать сниппет из выделения"` entry (line 313) from the `protocolRunner` object.
