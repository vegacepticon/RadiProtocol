# Sub-plan (cluster-5): Insert-snippet modal CSS: stronger keyboard highlight + top margin and vertical extension

## Synthesis Notes
- **Single-slice cluster.** The fan-in provided one design (slice 5, `depends_on: []`), so there is no intra-cluster overlap to merge. The phase below carries the design's decisions verbatim; no redesign, no TS/i18n/test surface.
- **Sibling-slice isolation preserved (the slice map's shared-caps regression warning).** Research precedent `164b8e6`/`c0bb3ee` (2026-06-14) recorded that a shared `height: 360px` / `max-height: 320px` cap broke the resizable inline runner, forcing `.rp-stp-inline-host` and `.rp-stp-modal-host` CSS to be split and `overflow: hidden` to be scoped to the picker host only. This slice honors that lesson by scoping **every** height override under `.rp-insert-snippet-modal` / `.rp-insert-snippet-picker-host`, so `.rp-stp-inline-host` (inline runner picker, `:28-32`), `.rp-stp-modal-host` (Snippet Manager move-to modal, `:248-256`), and `.rp-stp-editor-host` (node editor inline mount, `:249-262`) are untouched. Integration rule for any sibling cluster editing this stylesheet: do not relax these host scopes back to the global `.rp-stp-root > …` form.
- **Keyboard-highlight change is intentionally global across picker hosts.** `.rp-stp-row-highlighted` is not host-scoped. This is correct: keyboard nav runs in every host that mounts `SnippetTreePicker` (insert modal, inline runner, Snippet Manager move-to), and a stronger highlight is desirable everywhere. The mouse-hover token it diverges from (`--background-modifier-hover`) is applied per-rule, not globally, so no other rule changes behavior. Sibling clusters must keep the two tokens distinct — do not collapse the keyboard highlight back onto `--background-modifier-hover`.
- **Pinning invariant from slice 3 is preserved, not weakened.** `align-self: flex-start` is kept on `.rp-insert-snippet-modal` (content still grows downward from the pin). The bare list keeps `min==max==440px` so the per-keystroke `removeBody` + bare-list rebuild still sees a fixed-height box and does not recenter. The body (480px) and bare list (440px) preserve the original ~40px delta so drill view and search view stay visually consistent.
- **Citations are repo-root-relative.** All `file:line` references in this sub-plan use the `src/styles/snippet-tree-picker.css:…` form; the design's references to `inline-runner.css:71,92`, `protocol-editor.css:97`, and `snippet-manager.css:214-217` are likewise repo-root-relative and verified against the research's Code References block.
- **No cross-cluster ordering dependency.** Slice 5 touches only `src/styles/snippet-tree-picker.css`. No other cluster in this slice map edits that file (clusters 1–4 are footer removal / JSON cleanup / text-block deprecation / default Start node — all in `.ts` / `README` / `i18n`). This cluster may land in any order relative to the others.

## Risk Flags
- **r1** — The +120px / +120px height lift (body 360→480, list 320→440) plus the new `max-height: calc(100vh - var(--size-4-12))` cap must not regress the slice-3 no-recenter/no-jump invariant and must clamp cleanly on a short viewport. The design argues the min==max list height preserves the fixed box and the calc cap bounds overflow; the grade/validate panel should rule on whether manual UAT must cover (i) typing in the search box on a tall viewport (no recenter), and (ii) shrinking the window below the modal's natural height (cap clamps, list scrolls, no overflow).
- **r2** — The 2px `--interactive-accent` left stripe on `.rp-stp-row-highlighted` must remain visually distinct from the solid-accent `.rp-stp-select-folder-btn.is-committed` (`:283-293`) and must not visibly shift row content. The design makes no padding adjustment (matching the `[data-editing="true"]` precedent at `snippet-manager.css:214-217`); a reviewer should confirm the 1px net content nudge is imperceptible and that the stripe does not collide with the committed-folder-button accent in any host.

## Phase 1: Insert-snippet modal CSS: stronger keyboard highlight + top margin and vertical extension
### Changes
- `src/styles/snippet-tree-picker.css` — Rewrite the `.rp-stp-row-highlighted` rule at `:301-304` to declare `background: var(--background-modifier-active-hover)` and `border-left: 2px solid var(--interactive-accent)` (dropping the prior `background: var(--background-modifier-hover)` / `border-color: var(--background-modifier-border)`), mirroring the `[data-editing="true"]` active-row pattern in `src/styles/snippet-manager.css:214-217`.
- `src/styles/snippet-tree-picker.css` — Add a scoped enhancement rule `.rp-stp-row-highlighted .rp-stp-row-title { font-weight: var(--font-semibold); }` immediately after the rewritten `.rp-stp-row-highlighted` block, so the title of the keyboard-focused row sharpens without affecting un-highlighted rows or other hosts.
- `src/styles/snippet-tree-picker.css` — Edit the `.rp-insert-snippet-modal` rule at `:232-235` to set `margin-top: var(--size-4-6)` (was flush `margin-top: 0` / `0`), keep `align-self: flex-start` (the slice-3 pinning invariant), and add `max-height: calc(100vh - var(--size-4-12))` as a short-viewport safety cap (the `calc(100vh - var(--size-4-N))` form is the established tall-modal precedent at `src/styles/inline-runner.css:71,92`).
- `src/styles/snippet-tree-picker.css` — Raise the drill-view body height on `.rp-insert-snippet-picker-host .rp-stp-root > .rp-stp-body` from `360px` to `480px` (proportional ×1.33). The inner list is `flex: 1 1 auto` (`:40`), so it fills the taller body automatically.
- `src/styles/snippet-tree-picker.css` — Raise the bare search-result list height on `.rp-insert-snippet-picker-host .rp-stp-root > .rp-stp-list` from `min-height: 320px` to `{ min-height: 440px; max-height: 440px; }` (min==max), host-scoped so it overrides the global `.rp-stp-list { max-height: 320px }` at `:148` only inside the insert modal. The `> .rp-stp-list` direct-child selector still avoids the inner list inside `.rp-stp-body` (governed by `.rp-stp-body .rp-stp-list { flex: 1 1 auto }`). The min==max pair preserves the slice-3 per-keystroke no-recenter invariant: the `removeBody` + bare-list rebuild still sees a fixed-height box.
