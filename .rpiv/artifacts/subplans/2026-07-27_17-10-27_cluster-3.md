# Sub-plan: Deprecate text-block node (not creatable, still runnable)

## Synthesis Notes
- **Single-slice partial; no cross-slice overlap to merge.** This cluster contains only Slice 3 (`depends_on: []`), so there are no inter-slice overlaps, conflicts, or ordering constraints to reconcile within the cluster. The phase below is the slice's design passed through in plan-compatible shape.
- **Integration seam wired for the root merge.** The only owned seam that other clusters may touch is `EDITABLE_NODE_KINDS` (`src/views/protocol-editor-view.ts:256`). Its post-state is exported above so a sibling cluster that also edits this array (e.g., the loop→question merge cluster, which may add/remove `loop` from the dropdown) reconciles against `['start','question','answer','loop','snippet']` rather than the pre-state that still contained `'text-block'`. The two picker loop sites (`:769`, `:819`) are data-driven and require no change by any cluster.
- **Retention contract is load-bearing for downstream clusters.** The design deliberately leaves `'text-block'` in `RPNodeKind` (`src/graph/graph-model.ts:13`), `TextBlockNode` in the `RPNode` union (`:119`), the parser `case 'text-block'` (`src/protocol/protocol-document-parser.ts:31,210-218`), the runner `case 'text-block'` arm (`src/runner/protocol-runner.ts:711-724`), `nodeLabel`'s `case 'text-block'` (`src/graph/node-label.ts:23`), and `NODE_KIND_DEFAULTS['text-block']` (`src/views/protocol-editor-view.ts:251`) untouched. This keeps exhaustive `switch` narrowing over `RPNodeKind` compile-clean and keeps existing protocols runnable. Any future cluster that removes `'text-block'` fully must own the full cascade (model→parser→validator→runner→nodeLabel→color-map→picker→tests) per the `free-text-input` removal precedent — this cluster explicitly does NOT do that.
- **Start-picker decision settled, not re-litigated.** The slice map flagged whether `node-picker-modal.ts` should also drop text-blocks as open; the design resolved to KEEP them (runnable nodes are valid start points; the slice chose the softer deprecation variant). Recorded so the root merge does not re-open it. A harder-deprecation follow-up must edit `StartableNodeKind`, `KIND_LABEL_KEYS`, `KIND_LABELS`, `KIND_ORDER`, the `buildNodeOptions` text-block arm in `src/views/node-picker-modal.ts`, and `__tests__/node-picker-modal.test.ts`.

## Risk Flags
- **r1** — Orphaned i18n keys `protocolEditor.nodeKind.text-block` (`src/i18n/locales/en.json:97`, `ru.json:97`) and `protocolEditor.defaultNodeText.text-block` (`en.json:104`, `ru.json:104`) become runtime-dead after this slice (only readers were the two picker loops and the generic `defaultNodeText` lookup, none of which receive `'text-block'` anymore). They are KEPT to avoid touching i18n outside this slice's scope. Reviewers should rule on whether leaving dead keys is acceptable (recommended, defer to a cleanup slice) vs. removing them in this slice. No compile impact (template-literal lookups).

## Phase 1: Remove 'text-block' from EDITABLE_NODE_KINDS (not creatable, still runnable)
### Changes
- `src/views/protocol-editor-view.ts:256` — Remove the `'text-block'` element from the `EDITABLE_NODE_KINDS` array literal so it reads `const EDITABLE_NODE_KINDS: RPNodeKind[] = ['start', 'question', 'answer', 'loop', 'snippet'];`. This is the sole edit of the slice. The two array-driven picker loops — `openNodeKindPickerAtWorldPoint` (`:769-784`) and `openNodeKindPickerAndConnectAtWorldPoint` (`:819-824`) — require no change; they iterate `for (const kind of EDITABLE_NODE_KINDS)` and now render 5 choice buttons instead of 6.
- `src/views/protocol-editor-view.ts:251` — **No change.** `NODE_KIND_DEFAULTS['text-block']` is intentionally retained so `defaultColorForProtocolEditorNodeKind('text-block')` / `fieldsForProtocolEditorNodeKind('text-block')` stay compile-clean and available for any legacy display path.
- `src/graph/graph-model.ts:13,119` — **No change.** `'text-block'` stays in `RPNodeKind` and `TextBlockNode` stays in the `RPNode` union (full removal is out of scope; would cascade across model/parser/validator/runner/color-map/picker).
- `src/protocol/protocol-document-parser.ts:31,210-218` — **No change.** `VALID_KINDS` retains `'text-block'` and the parser `case 'text-block'` arm stays so existing protocols still parse.
- `src/runner/protocol-runner.ts:711-724` — **No change.** The runner `case 'text-block'` arm stays so static `content` auto-append and `snippetId`→`AWAITING_SNIPPET_FILL` transitions still fire for existing protocols.
- `src/graph/node-label.ts:23` — **No change.** `nodeLabel`'s `case 'text-block'` stays so validator error wording and runner captions remain in lock-step.
- `src/views/node-picker-modal.ts:9,22-29,56-63,92-106` — **No change.** The "Start from specific node" picker keeps listing text-blocks (deliberate: runnable nodes are valid start points; the softer deprecation variant was chosen).
- `src/i18n/locales/en.json:97,104` and `src/i18n/locales/ru.json:97,104` — **No change.** `protocolEditor.nodeKind.text-block` and `protocolEditor.defaultNodeText.text-block` are kept despite becoming runtime-dead (see Risk r1); removal is deferred to a cleanup slice.
