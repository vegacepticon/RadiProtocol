## 🔴 Critical

### Q1 🔴 Minimum bend floor can exceed the computed safe maximum `[precedent-weighted]`

**Where**
`.rpiv/artifacts/plans/2026-06-01_23-11-50_protocol-editor-edge-and-drag-fix.md:147`

**Code**
```typescript
return Math.max(MIN_BEND, maxBend);
```

**Why**
The plan computes `maxBend` from the available rank/normal deltas, then forces at least `MIN_BEND`. For very short non-straight forward routes where `maxBend < 8`, this violates the plan's own invariant that the first segment must remain non-negative and can reintroduce the folds/cusps this plan is meant to remove.

**Fix**
Clamp to the safe maximum instead of flooring above it, and add a short-delta route test that proves no segment backtracks.

**Alt**
Keep a visual minimum only when both available constraints are at least that minimum; otherwise return the safe smaller bend.

**Code**
```typescript

```

**Why**
The plan awaits a store write and then assigns `this.doc` without capturing the path being saved or rechecking that the view still displays that same protocol. If the view loads another protocol while the write is pending, the stale update can replace the active document state.
